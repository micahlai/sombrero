## Existing photo/message UI

The native macOS Swift/AppKit application uses `assets/polaroid-frame.png`, copied unchanged into `Sources/PetAssets/Resources/Polaroid/`. The resource is registered in `Package.swift` and loaded by `Sources/PetAssets/MessageArtwork.swift`.

Main UI files:

- `Sources/DesktopPet/PolaroidView.swift`: transparent key-capable native window, artwork canvas, vector brown-ink controls, project font, corner resize grip.
- `Sources/DesktopPet/MessageWindows.swift`: composer and inbox/viewer.
- `Sources/DesktopPet/MessageCoordinator.swift`: window, animation, camera, network, draft, and kept-card integration.
- `Sources/PetAssets/AppTypography.swift`: bundled **Matcha Style** font. It has one face; rich-text bold and italic use synthetic stroke/slant while preserving the message schema.

Composer behavior:

- New/text-only drafts default to live camera preview after the duck reaches 6b. Saved photo/video drafts reopen for review.
- Photo controls are at the top; the message editor is on the paper's lower lip, with small B/I/U controls, date, and Send.
- Taking a photo does not send it. Capture and Send are explicit separate actions.
- Send stages a durable outbox entry and disables resubmission. The composer closes **immediately on server acknowledgment of that specific message**, not on local enqueue or recipient reading.
- Offline sends remain queued and the composer remains visible until acknowledged or manually closed.
- `composerSendID` and `closingSentComposer` prevent late acknowledgments from closing a newer draft and avoid treating a successful send as canceled camera capture.

Viewer behavior:

- Keep detaches a loaded card from the active viewer and releases the duck's photo routine, while retaining an independent native window.
- Multiple kept windows can coexist with another viewer/composer, Bible reading, hiding the duck, and sleep.
- Closing an old kept window cannot cancel a newer viewer's routine.
- Kept windows are session-only; disconnect/profile change or app shutdown closes them.
- Media must load and be visibly presented before read acknowledgment. Metadata, failed media, or canceled presentation do not count as reading.
